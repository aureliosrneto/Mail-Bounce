# Security Policy / Política de Segurança

## English

### Reporting a vulnerability

Please **do not open a public issue with exploit details, credentials or private messages**.

Use GitHub's **Report a vulnerability** feature under the repository's Security tab, if enabled. Otherwise, contact the repository maintainer privately through an established, verified channel. Never post secrets in screenshots, logs or public discussions.

A vulnerability report should include the affected version, reproduction steps, impact and a minimal sanitized example. Do not include actual users' messages or account credentials.

### Scope and safeguards

Mail Bounce is a Thunderbird extension. Before using it, inspect requested extension permissions and verify the recipients of sensitive messages. Sending redirected email can be affected by SMTP, SPF, DKIM and DMARC policies. Never commit API keys, tokens, passwords, profile databases, message archives or private user data.

There is no published security support timeline at this stage.

## Português (Brasil)

### Comunicação de vulnerabilidades

**Não abra uma issue pública com detalhes de exploração, credenciais ou mensagens privadas.**

Utilize **Report a vulnerability** na aba Security do GitHub, caso esteja habilitado. Caso contrário, contate o mantenedor por um canal privado e verificado. Nunca compartilhe segredos em capturas de tela, logs ou discussões públicas.

Informe a versão afetada, os passos de reprodução, o impacto e um exemplo mínimo sem dados pessoais.

### Escopo e proteções

O Mail Bounce é uma extensão do Thunderbird. Revise as permissões solicitadas e confirme os destinatários de mensagens confidenciais. O envio de mensagens redirecionadas pode depender das políticas SMTP, SPF, DKIM e DMARC. Não inclua tokens, senhas, bancos de perfis, arquivos de e-mails ou dados privados no repositório.

Ainda não há um período de suporte de segurança formalmente publicado.
